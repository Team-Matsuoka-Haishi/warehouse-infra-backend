## 1. 本書の目的・位置付け

本書は、物流倉庫における設備保守および部品在庫管理DXプロジェクトについて、基本設計の方向性を整理するものである。

本プロジェクトでは、段階1で設備情報の登録・更新および手順書の閲覧・登録・更新機能を作成し、その後、段階2で在庫管理機能を追加する。今回の設計では、段階1の機能を具体的に整理するとともに、段階2の機能についても初期案として画面構成や操作の方向性を示す。あわせて、システム全体の仕組みとデータ管理方針を整理する。

段階1・段階2の両方をお客様からの依頼範囲として設計対象に含める。ただし、実装は段階1を先行し、その結果をお客様に確認いただいたうえで、段階2の画面項目・操作方法・運用方法を再検討してから実装する。詳細な項目定義、システム間のデータ連携方法、例外処理、運用ルールなどは、レビューと後続設計で具体化する。

## 2. システム概要

物流倉庫で使用する設備の保守情報および部品在庫情報をデジタル化し、保守作業の効率化と在庫情報の正確な把握を目指す。

### 2.1 対象ユーザー

| ユーザー | 主な利用内容 |

| 利用者 | 設備情報の登録・確認・更新、設備の検索、手順書の検索・閲覧・登録・更新。在庫管理機能は段階2で利用する。 |

※現時点では、設備保守担当者と手順書登録担当者を分けず、「利用者」として扱う。また、利用者向け・管理者向けの画面や権限を分けるかどうかは今後検討する。

### 2.2 開発の段階分け

本システムは、次の2段階に分けて開発する。

- **段階1：設備情報・手順書管理**

段階1を先行して開発する。段階1の完成後、お客様に実際の画面や操作を確認いただき、その結果やご要望を踏まえて段階2の内容を見直す。段階2の内容についてお客様と合意したうえで、実装を進める。

段階2の内容は初期案として扱い、段階1の開発結果を踏まえたお客様との確認後に確定する。

## 3. 対象範囲

### 3.1 段階1の対象

段階1では、設備情報の管理と、設備に紐づく手順書の閲覧・登録を対象とする。

**設備情報の管理**
- 設備情報を新規登録・更新できるようにする。
- 設備名は設備マスターから選択し、設備番号は利用者が入力する。
- 設備番号が既に登録されている場合は、重複登録できないようにする。
- 設備情報の削除は行わない。使用しなくなった設備は「使用停止」として管理する。
- 設備名または設備番号で設備を検索できるようにする。

**手順書の閲覧**
- 選択した設備に紐づく手順書を一覧表示し、内容を閲覧できるようにする。
- 通常の一覧には、承認済みの最新版のみを表示する。

**手順書の登録・更新**
- 手順書を新規登録できるようにする。
- 更新時は既存の手順書を上書きせず、新しいバージョンとして登録する。
- 旧バージョンは履歴として保存し、削除しない。
- 新しいバージョンは内容確認・承認後に公開する。承認前は現在公開中の最新版を維持する。

**設備情報と手順書の関係**

設備情報を親、手順書を子として管理し、1つの設備情報に複数の手順書を紐づける。設備情報には設備名・設備番号などを持たせ、手順書には手順書名・対象作業・更新日・バージョンなどを持たせる。

### 3.2 段階2の対象

段階2では、部品在庫を管理するため、次の機能を対象とする。

- 部品情報と在庫数量の検索・確認
- 部品の入庫・出庫の登録
- 入出庫履歴の確認
- 必要に応じた部品の引当・予約

各画面の構成案や主な操作案は「8. 在庫管理画面の基本方針」に記載する。具体的な項目・操作・運用ルールは、段階1の開発結果をお客様に確認いただいた後、要望を踏まえて再検討・合意する。

### 3.3 今後の検討・拡張事項

- 手順書の承認担当者および具体的なレビュー方法
- 手順書に不備・不明点があった場合の問合せ先・報告方法
- バージョン番号の付け方、旧バージョンの保存期間、履歴の確認方法
- 手順書の登録・更新時に必要な入力項目や登録方法の詳細

## 5. 設備検索画面の基本方針

### 5.1 検索・表示方針

- 設備名または設備番号で検索する。
- 設備名と設備番号のどちらかに入力内容が含まれる場合に検索結果として表示する方式を想定する。
- 検索ボタンを押して検索を実行する。
- クリアボタンで検索条件を消去する。
- 初期表示では使用中の設備を対象とする。
- 「使用停止設備も表示」チェックボックスにより、使用停止設備を検索対象に含める。

**使用停止設備の表示・選択ルール**

- 使用停止設備は検索結果に表示する。
- 使用停止設備は、新たな対象設備として選択できないようにする。
- 検索結果は一覧形式とし、設備名・設備番号・使用状態を表示する。
- 検索結果は設備番号の昇順で表示する。
- 設備名をクリックして設備を選択する。
- 検索結果が0件の場合は「該当する設備がありません」と表示し、条件を変更して再検索できるようにする。

### 5.2 設備情報の管理方針

- 設備情報はSalesforceで管理する。
- 設備情報は、設備名と設備番号などを1つの設備レコードとして管理する。
- 設備名は設備マスターで管理し、設備情報の登録時に登録済みの設備名から選択する。
- 設備番号は利用者が入力する。既に登録されている設備番号と重複する場合は登録できないようにする。
- 設備情報の新規登録・更新に対応する。設備情報の削除は行わず、使用しなくなった設備は「使用停止」に変更する。
- 設備名マスターの登録・変更を行う担当者や管理方法は今後検討する。
- 必須入力など、上記以外の詳細な入力制御は今後の検討事項とする。
- 最近使用した設備とよく使用する設備は別々の表示枠を設ける。
- 表示件数や集計期間などの詳細条件は未確定とする。

### 5.3 設備情報と手順書の関係

設備情報を親、手順書を子として管理する。1つの設備情報に対して、複数の手順書を紐づけられる構成とする。

- 設備情報：設備名、設備番号、使用状態などを管理する。
- 手順書：手順書名、対象作業、更新日、バージョンなどを管理し、対象となる設備情報に紐づける。
- 設備名は設備マスターから選択する。設備番号は設備情報の項目として利用者が入力し、重複を認めない。

この関係により、利用者は対象設備を選択して、その設備に紐づく手順書を確認できる。設備名マスターの管理担当者や具体的な管理方法は今後検討する。

## 6. 手順書一覧・閲覧画面の基本方針

### 6.1 手順書一覧画面

設備検索画面で選択した設備に関連する手順書を一覧表示し、利用者が確認したい手順書を選択する。

一覧に表示する項目は以下を基本とする。

| 表示項目 | 内容 |
|---|---|
| 手順書名 | 手順書のタイトル |
| 対象作業 | 対応する作業・故障の内容 |
| 更新日 | 手順書の最終更新日 |

### 6.2 手順書閲覧

選択した手順書の内容を画面上で確認できる構成とする。PDFファイル形式での表示を想定し、利用者が別のアプリケーションへ移動せずに確認できることを目指す。

手順書の表示内容や操作方法、PDFの保存先および画面内での具体的な表示方法は、今後の設計・技術確認で決定する。

## 7. 手順書登録・更新画面の基本方針

### 7.1 登録・更新

手順書の新規登録および更新を段階1の対象とする。手順書を更新する場合は、公開中の手順書を上書きせず、新しいバージョンとして登録する。手順書の削除は行わず、過去のバージョンは履歴として保存する。

### 7.2 バージョン管理・公開

同じ設備・手順書について、利用者が通常確認する手順書は、承認済みの最新版に統一する。通常の手順書一覧には最新版のみを表示し、過去のバージョンは履歴として保持する。必要に応じて過去のバージョンを確認できるようにする。

新しい手順書または新しいバージョンを登録した場合は、内容の確認・承認を行ったうえで公開する。承認されるまでは、現在公開中の最新版を維持する。これにより、確認途中の手順書が通常の閲覧対象になることを防ぐ。

承認担当者および具体的なレビュー方法は今後検討する。バージョン番号の付け方や履歴の詳細な表示方法も今後具体化する。

### 7.3 問合せ・不備への対応

手順書に誤りや不明点があった場合の問合せ先および報告方法は、今後の検討事項とする。現時点では、問合せ専用機能や具体的な連絡手段は段階1の対象として確定しない。

### 7.4 画面・権限

手順書の登録・更新に必要な情報、登録方法、登録後の確認方法などの詳細は今後検討する。利用者向け・管理者向けに画面や権限を分けるかどうかも、現時点では確定せず、今後検討する。

## 8. 在庫管理画面の基本方針（段階2）

在庫管理画面は段階2で作成する。お客様から依頼された機能であるため、本書では初期の画面構成案と主な操作案を整理する。

### 8.1 画面構成案

| 画面 | 目的 | 主な表示項目・操作案 |
|---|---|---|
| 部品検索・在庫一覧画面 | 管理対象の部品と在庫状況を探す | 部品番号・部品名で検索し、部品番号、部品名、現在庫数量などを一覧で確認する。 |
| 部品情報・在庫詳細画面 | 選択した部品の情報と在庫状況を確認する | 部品の基本情報、現在庫数量、入出庫履歴を確認する。 |
| 入庫登録画面 | 部品を受け入れた情報を記録する | 対象部品、入庫数量、入庫日、備考などを入力して登録する案。 |
| 出庫登録画面 | 部品を使用・払い出した情報を記録する | 対象部品、出庫数量、出庫日、使用先・用途、備考などを入力して登録する案。 |

※上記は基本設計段階の画面構成案であり、画面を分けるか一つにまとめるかも含めて、お客様との確認後に決定する。

### 8.2 主な操作案

1.  部品番号または部品名で部品を検索する。
2.  検索結果から対象部品を選び、現在庫数量を確認する。
3.  部品を受け入れた場合は入庫情報を登録する。
4.  部品を使用・払い出した場合は出庫情報を登録する。
5.  入出庫の登録内容を在庫数量に反映する。
6.  必要に応じて、対象部品の入出庫履歴を確認する。

要件として、保守作業で使用する部品の在庫確認・引当を行う想定がある。引当・予約の具体的なタイミングや、引当数量の扱い、保守作業完了時の出庫反映方法は、お客様との確認事項とする。

### 8.3 主な表示項目案

| 項目 | 内容 |
|---|---|
| 部品番号 | 部品を識別する番号 |
| 部品名 | 部品の名称 |
| 現在庫数量 | 現在保管されている数量 |
| 入庫数量 | 登録する入庫の数量 |
| 出庫数量 | 登録する出庫の数量 |
| 入出庫日 | 入庫または出庫を行った日 |
| 用途・使用先 | 出庫した部品の使用目的や使用先 |
| 備考 | 補足事項 |

※最低在庫数、保管場所、発注先、引当可能数などは、必要性をお客様に確認してから追加を判断する。現時点では確定項目としない。

### 8.4 段階2の内容を確定する進め方

段階2の機能は本書で初期案を示すが、段階1の開発完了後にお客様へ実際の画面・操作を確認いただく。その際に得られた意見や、段階1で明らかになった運用上の課題を踏まえて、段階2の画面項目・操作方法・運用方法を再検討する。

再検討した内容についてお客様と合意した後、段階2の詳細設計および実装を進める。

## 9. システム全体の仕組み・技術方針

プロジェクト全体では、Salesforceを業務情報の管理や画面表示に利用し、AWSの連携サービスを通じてデータ連携を行う方針である。また、部品在庫情報は開発用の実行環境上に用意するデータベースで管理する構成を想定する。

段階1ではSalesforceを中心に手順書の閲覧・登録機能を作成する。閲覧機能と登録機能は、いずれも段階1に含める。段階2の在庫管理機能や、保守作業に伴う部品消費の連携については、後続の設計で詳細を整理する。

## 10. データ管理方針

| データ | 管理場所 | 主な役割 |
|---|---|---|
| 設備情報 | Salesforce | 設備の基本情報を管理する。 |
| 手順書情報・PDF | Salesforceを候補とする | 手順書の検索・閲覧・登録に利用する。具体的な保存方式は確認事項とする。 |
| 保守案件・作業記録 | Salesforce | 保守作業に関する情報を管理する。 |
| 部品基本情報 | 部品在庫を管理するデータベース | 部品の基本情報を管理する。 |
| 部品在庫数 | 部品在庫を管理するデータベース | 部品の現在庫数量を管理する。 |
| 入出庫履歴 | 部品在庫を管理するデータベース | 部品の入庫・出庫履歴を管理する。 |

データの正となる管理先は、要件定義書の方針に従い、保守案件の業務記録はSalesforce、部品在庫の現在数は部品在庫を管理するデータベースとする。
